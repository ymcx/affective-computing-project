The goal of this project is to answer whether large language models (LLMs) would be able to better take the user's emotional intensity into account during inference if given an explicit score. Pretrained LLMs are generally trained into chatbots by fine-tuning them on a supervised instruction dataset and by aligning them via reinforcement learning from human feedback (RLHF) [1]. RLHF by definition makes the model less accurate with regards to the datasets it's been trained on, since after all, in RLHF the model is rewarded on behavior that matches the preferences of its trainers, not datasets. Additionally, inference providers more often than not use prompt engineering by defining custom system prompts to further alter the models. Prompt engineering is conveinient, since it allows tailoring generic LLMs to all kinds of applications without necessarily having to fine-tune them.

By utilizing RLHF and prompt engineering we obtain models that are more often than not overly helpful and verbose, both of which can be infered as inapropriate depending on the context. Despite the astonishing reasoning abilities of the most powerful models, even they struggle with formulating their responses in a way that would take user frustration effectively into account. Models should be able to better adapt to the current situation by for example answering in a clear and concise way without constantly apologizing if the user is clearly irritated.

As stated before, chatbots are trained to be helpful using human input, which, on top of other things, includes taking care of user frustration. As a matter of fact, Claude Code, the agent built on top of Anthropic's flagship Claude chatbot, has a sophisticated frustration detection system built-in [2]. If nothing else, this should work as a clear indication of how hard it is to fix the problem by purely using fine-tuning and reinforcement learning, if even the top competitors are unable to do so without the help of external software.

The novelty of this project lies in the fact that, similar to Claude Code, my system is also independent of the underlying model. I propose fine-tuning a model to classify input text into a scalar score representing negative emotional intensity, which can then be provided to an LLM as a tool. The hypothesis is that the LLM can make use of the tool and its score to better understand the user's emotional state during reasoning.

More specifically I fine-tuned Google's encoder-only BERT model's base variant into a linear classifier that returns the score as a floating point number ranging from 0.0 to 1.0 given some textual input [3]. As for the dataset, I used Massive Text Embedding Benchmark's Toxic Conversations dataset, which consists of 50,000 textual prompts annotated as either toxic or non-toxic. I took a random sample of 10,000 entries and labelled each using DeepSeek V4.1 Flash (low) in terms of the negative emotional intensity. I trained the model for three epochs using a learning rate of 5e-5 and with a batch size of 16. I chose fused torch AdamW as the optimizer and enabled bfloat16 floating-point format. The fine-tuned model was then provided as a tool to two LLMs capable of reasoning: DeepSeek V4.1 Flash (max) and Cohere's North Mini Code. The results were acquired by comparing output of each model against a set of pre-defined prompts with and without access to the tool. 

BERT is widely regarded as one of the key breakthrough models that significantly advanced research in artificial intelligence following its publication in 2018 [3]. What makes BERT particularly useful for my purpose is its relatively small size in terms of parameters. A small model makes training faster and more accesible to people with less powerful hardware. It also helps with avoiding overfitting in cases where there isn't as much of a need for a more sophisticated model. DeepSeek V4.1 Flash was initially chosen for annotating the dataset and generating responses for the queries simply because it was the only paid model I had access to through an API. Cohere's North Mini Code was later added to the mix due to it better representing a wide range of models that are smaller than the aforementioned one. The training parameters were chosen either by sticking with the default, recommended values or alternatively by tuning each for my GPU, a measly GeForce GTX 1060. The dataset size was chosen as a round number that was sufficiently large to train an effective classifier while remaining small enough to keep the cost of annotation inference manageable.
 
LLMs weren't used for writing or editing this document or for writing the code used in this project. AI was used for annotating the dataset, training the classifier and for generating the responses for the pre-defined queries.
